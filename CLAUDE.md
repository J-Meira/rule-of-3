# CLAUDE.md

Project instructions for Claude Code. It replaces the old Copilot instructions.

## What this is

Rule of 3: a small React PWA that solves rule-of-three calculations, keeps a history, and works in English, Portuguese and Spanish. Published at https://rule-of-3.jm.app.br from GitHub Pages.

- React 19, TypeScript 6, Vite 8 (rolldown), `@vitejs/plugin-react` 6, `vite-plugin-pwa` 1.x with `@vite-pwa/assets-generator` 1.x
- `@j-meira/mui-theme` **3.x** (ESM only) on Material UI **9** and MUI X Date Pickers 9. The theme's peer dependencies are installed here directly: `@mui/material`, `@mui/x-date-pickers`, `@emotion/react`, `@emotion/styled`, `formik`, `notistack`, `dayjs`, `react-icons`.
- Redux Toolkit for state, Formik + Yup for the form, Day.js, SCSS.
- ESLint 10 flat config: `typescript-eslint`, `@eslint-react/eslint-plugin`, `eslint-plugin-react-hooks` 7, `eslint-plugin-react-refresh`, `eslint-plugin-import-x`, `eslint-config-prettier`.
- pnpm 12, Node 22.13+ locally, Node 24 in CI and Docker.

## Commands

```bash
pnpm install        # @j-meira scope needs GitHub Packages auth (see README)
pnpm dev            # vite dev server
pnpm build          # tsc && vite build
pnpm preview
pnpm lint           # eslint . --max-warnings 0
```

`pnpm-workspace.yaml` approves the build scripts pnpm 12 asks about (esbuild, sharp); without it `pnpm build` refuses to run. It also overrides `sharp` to a single version, because `sharp-ico` still declares an old one. TypeScript stays on 6.x until `typescript-eslint` supports 7.

## Code rules

### Three hard rules

**1. No `else`.** Early returns, ternaries, or a switch / object lookup.

```tsx
if (error) return null;
return <Component />;
```

**2. `const` by default, never `var`.** `let` only when a value must be reassigned.

**3. Do not add comments.** No explanatory comments in new or refactored code, no commented-out code. Keep an existing comment only while it still applies.

### Everything else

- `memo` for pure components and `useCallback` for handlers passed as props are the existing convention here; keep it, and always set `displayName` on a `memo` component.
- Formik + Yup for forms; use the theme's `Input` models (`number`, `select`, `icon`, ...) rather than raw MUI inputs. Follow `Main.tsx`.
- Every user-facing string goes through the dictionary (`getDictionary`) in all three languages.
- Keep the PWA working: assets come from `pwa-assets.config.ts`, the service worker is generated by `vite-plugin-pwa`.
- Styles live in `src/scss/`; the theme styles are imported once with `@use '@j-meira/mui-theme/scss/index.scss'`. Test dark mode.

## MUI 9 and mui-theme 3 conventions

- Grid v2 only: `<Grid size={{ xs: 12, md: 6 }}>` or `<Grid size={12}>`. Never `item`, `xs=`, `md=`. `Grid2` does not exist.
- System props are gone from `Box`, `Grid`, `Stack`, `Typography`, `Link`: `display`, `mt`, `p`, `color="primary.main"`, `justifyContent`, ... all go in `sx`.
- `slotProps.input` / `slotProps.htmlInput` instead of `InputProps` / `inputProps`; `slots` instead of `components`.
- Import the theme only from the package root (`@j-meira/mui-theme`) or `@j-meira/mui-theme/scss/*`. Deep imports into `dist/` are blocked.
- Never let theme-only props (`model`, `grid`, `noGrid`, `searchChange`, `action`) reach a native element.
- Theme components used here: `Button`, `Input`, `Header`, `PopUp`, `DarkSwitch`, `MultiProvider`, `useMultiContext`, `useToast`. The theme also offers `DataTable*`, `DatePicker`, `FileUpload`, `SearchGeneric`, `SideBar`, `SideBarItem`, `MainContainer`, `DialogBox`, `Tabs`, `TreeListItem`, `BreadcrumbBar`, `ListMenu`, `GroupCard` and the hooks `useCookies`, `useDebounce`, `useWindowDimensions`.
- Upgrading the theme: run the `/mui-theme-upgrade` skill in this repo.

## Deploy

- `.github/workflows/pages.yml` builds and deploys `dist/` to GitHub Pages on every published release, or manually from Actions. The version badge comes from the release tag via `.env` (`VITE_VERSION`, `VITE_V_DATE`).
- `.github/workflows/docker.yml` still builds the Docker image on release; the Dockerfile takes an `NPM_TOKEN` build arg.
- Installing `@j-meira/mui-theme` in CI uses `setup-node` with `registry-url` and `NODE_AUTH_TOKEN` from the `NPM_PASS` secret (a GitHub PAT with `read:packages`).
